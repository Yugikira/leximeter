特征发现 discover

把两组文本丢给它，让大语言模型自己找出"它们到底差在哪里"，再把每个特征量化成"在多少条文本中成立"，直接产出可检验的研究假设。

质性分析类LLM 核心

这是什么

在质性研究中你常会面对这样的问题：支持者与反对者的发言、A 公司与 B 公司的年报、改革前后的话语——它们显然不一样，但你一时说不清差在哪儿，也没有一张现成的编码表。

discover 就是为你解决这个问题的：它不要求你事先定义任何特征，而是走一条完整的"特征发现"链路——

  • 找差异：把两类文本逐条配对，让模型写下每条"区别点"（比如：circle 是乐观语气，square 是警示语气）；
  • 归并成标签：几十条零碎的差异描述太散，模型再把这些差异归并成几个互斥的"大类"（标签），每个标签自带定义；
  • 套回数据量化：把每个标签当成一个问题，逐条文本判断它是否成立，统计出占比，回答"这个特征到底有多常见、是否只属于某一类"。

它支持两种用法：两列对比（circle 列 = 你关心的类，square 列 = 对照类，推荐，能产出净占比）与单列挖掘（只给一列文本，让模型直接标出其中的特征片段）。

什么时候用 当你没有预设特征清单，想探索"两类文本究竟差在哪"、为下一步研究生成假设时。发现出的标签可以接着用来手工完善编码手册，或者转成 分类 的标签做大样本验证。如果你已经有明确假设，直接用 分类；标签由模型生成，是"建议"而非"结论"，正式研究请人工审读一遍再使用。

怎么用

三步：准备两类文本（或一列文本）→ 调用 → 读取汇总表。数据是一个表格（pandas DataFrame），circle/square 各占一列。

import leximeter
import pandas as pd

# 1. 你的数据：两类文本各一列（circle = 你关心的类，square = 对照类）
df = pd.DataFrame({
    "circle": [
        "AI assistants handle routine support tickets, freeing staff for creative work.",
        "Renewable energy costs keep falling; solar is now the cheapest power source.",
        "Telemedicine reaches rural patients who previously had no local specialists.",
    ],
    "square": [
        "Algorithmic feeds deepen polarization and erode public discourse daily.",
        "Mass surveillance tools quietly expand with each new security law.",
        "Automation is hollowing out middle-skill jobs faster than retraining helps.",
    ],
})

# 2. 调用：discover 自己找差异、归并标签、再逐条量化
result = await leximeter.discover(
    df,
    circle_column_name="circle",
    square_column_name="square",
    save_dir="my_study/discover",
    bucket_count=10,          # 差异条目最终归并成几个标签
    model="deepseek-v4-flash",  # 或任何已配置的模型
)

# 3. 最重要的输出：每个特征的"净占比"汇总表
print(result["summary"])
result["summary"].to_csv("my_study/discover_summary.csv", index=False)

如果只想挖一列文本的特征（不对比两类），把 column_name="text" 传给 discover，其他照旧；该模式不产出 summary 净占比表。

结果里有什么

result["candidates"]        # 原始差异候选（Compare 或 Codify 阶段产出的术语 → 定义）
result["compare"]           # pair 模式：逐对差异表（attribute / explanation 两列）
result["buckets"]           # 归并后的标签：{标签: 定义}（也即汇总表的 label 列）
result["bucket_df"]         # 同上，表格形式（bucket / definition 两列）
result["classification"]    # 原数据 + 每个标签的 {label}_actual / {label}_inverted 两列
result["summary"]           # pair 模式：每个标签的净占比汇总表

所有中间产物都会保存在 save_dir（compare / bucket / classify 子目录），并打包成 discover_results_snapshot.json 和 discover_results_export.zip（zip 内含全部表格的 CSV），方便检查与续跑。

实现原理（简版）

整条流水线由三个现成任务串起来，理解它有助于判断结果该信多少：

  1. 找候选特征（Compare / Codify）：pair 模式下，把 circle 与 square 逐条配对，让模型写出"这条 circle 与这条 square 在哪些方面不同"，每条差异配一句解释；单列模式改用动态编码（codify），直接在文本中标出特征片段。这一步产出的候选可能几十上百条，很碎。
  2. 归并成标签（Bucket）：候选太碎无法直接用。归桶任务经过"生成 → 缩减 → 定稿"三轮投票（repeat_bucketing / repeat_voting 控制次数），把原始差异归并成 bucket_count 个互斥的大类，每个标签自带一段定义。
  3. 套回数据量化（Classify）：把每个标签从"circle 的视角"描述一遍（正向），再对调成"square 的视角"（反向，模型会把描述里的 circle/square 互换），于是每个标签变成 {label}_actual 与 {label}_inverted 两个问题。然后逐条文本投票：每段文本判断该特征是否成立（n_runs 次重复，取多数；判定阈值 min_frequency）。
  4. 净占比（Summary）：对每个标签统计正向成立的比例（actual_pct）、反向成立的比例（inverted_pct），净占比 net_pct = 实际 − 反转（百分点）。

为什么要"实际 − 反转"而不是只看实际占比？因为模型可能系统性"容易打勾"——对某些表述总是倾向于说"存在差异"。反向问题提供了一个基准线：如果某特征只是模型偏好造成的假象，那它正向、反向成立的频率应该差不多，净占比会趋近 0；净占比越接近 ±100，越说明这是一个真实的、方向明确的区分特征。这和问卷里用反向题控制应答偏差是同一个统计思想。

给模型的提示词（概括）

Compare 提示词结构（简化为要点） 这是第 1 条文本（circle）："…circle 文本…"
这是第 2 条文本（square）："…square 文本…"
请找出这两条文本在内容、语气、结构上的差异，重点找能区分两类文本的特征。
对每条差异输出 JSON：{"attribute": "差异点的一句话描述", "explanation": "为什么这是差异"}
Classify 提示词结构（简化为要点） …circle 文本… 是研究对象，…square 文本… 是对照。
请判断以下特征是否成立："…标签定义…"
正向（actual）：该特征描述了 circle 而没有描述 square；
反向（inverted）：该特征描述了 square 而没有描述 circle。
输出 JSON：{"actual": true/false, "inverted": true/false}

归桶阶段的提示词核心是"把下面这些零散差异归并为 N 个大类，每类互斥且自带定义"，并经过多轮投票取多数，降低单次抽样的随机性。

参数设置

参数默认值说明
circle_column_name / square_column_nameNonepair 模式（推荐）：你关心的类与对照类的列名，两者必须同时给出。
column_nameNone单列模式：只给一列文本，动态编码直接挖特征。与 pair 模式二选一，不能都给。
save_dir（必填）保存中间产物与结果快照的目录（自动创建，含 compare/bucket/classify 子目录）。
bucket_count10差异条目最终归并成几个标签。想得到更细的发现就调大。
modelgpt-5.4-mini使用的模型名；默认从环境变量 LEXIMETER_MODEL 读取。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
n_runs1第三步分类时每段文本投票几次。大于 1 时取多数，降低随机波动。
min_frequency0.6分类判定阈值：n_runs 次中标记为真的比例 ≥ 该值才算"成立"。
additional_instructionsNone追加给各阶段任务的额外指令（例如"忽略品牌名差异"）。
max_words_per_call1000单列模式动态编码时，每次请求处理的文本上限（词数）。
max_categories_per_call8单列模式动态编码时，每次请求最多输出的特征类别数。
modality"text"文本类型提示："text"（段落）或 "entity"（短实体）。影响提示词措辞。
n_terms_per_prompt250归桶时每个提示词里放多少条原始术语。
repeat_bucketing5归桶"生成"阶段的重复次数（每次提出一套桶方案，再取多数）。
repeat_voting25归桶"投票"阶段的重复次数。
next_round_frac0.25归桶多轮缩减时每轮保留的候选比例。
top_k_per_round1归桶每轮每组保留的前几个候选。
raw_term_definitionsTrueTrue 时把候选特征连同其定义一起喂给归桶（推荐）；False 只喂术语名。
reset_filesFalseTrue 时清空 save_dir 重新跑；False 时断点续跑（跳过已完成条目）。
client / embedding_client / search_toolNone注入自定义模型客户端 / 嵌入客户端 / 搜索工具（进阶用法）。
