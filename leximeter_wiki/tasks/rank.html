排序 rank

让大语言模型两两比较文本之间的相对强弱，再用统计模型换算成可直接比较的排名分数（z 分数）。

测量类LLM 核心

这是什么

有些属性很难定义"绝对刻度"——比如"这条推文有多乐观？0 分是什么样、100 分是什么样？"说不清楚，但让你比较两条之间谁更乐观就容易得多。于是 rank 换了个思路：

  • 把文本两两配对，请模型对每一对判断"哪一段在某属性上更强"（就像网球积分赛里两两对决）；
  • 把所有对决结果交给 Bradley–Terry 统计模型，反推出每段文本的"实力值"（就像根据胜负记录给选手算积分）；
  • 最后把实力值标准化成 z 分数（均值 0、标准差 1），每段文本、每个属性得到一列可以直接排序和比较的数值。

每个属性会输出三列：{属性名}（z 分数，最直观）、{属性名}_raw（原始实力估计，中心化后均值为 0）、{属性名}_se（标准误，越小表示估计越有把握）。

什么时候用 当你的研究只需要"谁比谁强"的相对次序（哪条新闻最令人乐观、哪些评语最愤怒、哪个候选人最有吸引力），或属性的绝对刻度难以定义时。如果属性能说清"0 分到 100 分各是什么意思"，直接打分更简单，用 评分。

怎么用

三步：准备数据 → 定义属性 → 调用。数据是一个表格（pandas DataFrame 或 CSV），其中一列是你的文本。

import leximeter
import pandas as pd

# 1. 你的数据：一列文本（推文、新闻标题……）
df = pd.DataFrame({"text": [
    "Low-key hyped for on-device models - privacy win without the lag.",
    "That take is clown shoes - learn the basics before posting.",
    "Empirical evidence suggests platform concentration exacerbates rent extraction.",
]})

# 2. 定义要排序的属性（键 = 属性名，值 = 给模型的比较标准说明）
attributes = {
    "optimism": "How optimistic the text is about technology.",
    "formality": "How formal the language is.",
}

# 3. 调用
result = await leximeter.rank(
    df, "text",
    attributes=attributes,
    save_dir="my_study/rankings",
    model="deepseek-v4-flash",   # 或任何已配置的模型
)

回到数据里

返回的表格就是在你原来的表格上追加了每个属性三列。z 分数可直接用来排序、做相关或回归。可以 result.to_csv("rankings.csv") 保存后导入 Stata / R 分析。

实现原理（简版）

想象组织一场网球积分赛：我们不知道选手的水平，就让选手两两对决、看谁赢谁；打足够多场后，根据全部胜负记录就能反推出每个人的"实力值"。rank 做的正是这件事——只是"对决"由大语言模型当裁判。整个过程：

  1. 安排对决：每一轮挑选"最值得问"的文本对——优先安排实力接近的文本（当前分数排名相邻的）和把握最小的文本（标准误大的），外加少量随机组合，确保每段文本每轮出场固定次数（matches_per_round）。
  2. 对决：把一对文本交给模型，对每个属性判定谁更强。文本在提示词里的左右位置是随机分配的，避免顺序偏差。
  3. 拟合（Bradley–Terry 模型）：把全部历史对决结果喂给 Bradley–Terry 模型，反推出每段文本的实力值——就像根据所有比赛的胜负记录给选手算积分。平局与"信息不足"同时计入双方。learning_rate 是拟合时的一个平滑小量，防止出场次数少的文本得分过于极端。
  4. 中心化与标准化：把每个属性的实力值减去均值、除以标准差，得到 z 分数（均值 0，约 68% 的文本落在 -1 到 +1 之间），不同文本、不同批次之间可以直接比较。标准误（_se）表示估计的不确定性。
  5. 多轮迭代：默认跑 5 轮，每轮结束都用全部历史重新拟合一次（轮次越多排名越准）。每一轮的对决记录都会存盘，中断后可从断点续跑。

给模型的提示词（概括）

Rank 提示词结构（简化为要点） 以下是两段文本，circle 与 square 只是随机分配的代号，顺序没有任何含义：
circle："…文本 A…"　square："…文本 B…"
对每个属性判定哪一段更强，输出 JSON：
{"属性名": "circle" 或 "square" 或 "draw" 或 "insufficient signal"}
规则：只依据直接的文本证据，不从其他属性推断；两段都没有直接信号时用 "insufficient signal"；只有确实难分伯仲才用 "draw"。

注意四个判定选项的区别："circle/square" 是一方更强，"draw" 是双方都存在信号但难分伯仲，"insufficient signal" 是双方都几乎没有直接信号。每个属性的定义写得越清楚，裁判尺度就越一致。

参数设置

参数默认值说明
df（必填）你的数据表格（pandas DataFrame），须包含文本列。
column_name（必填）数据中文本所在列的列名。
attributes（必填）字典：属性名 → 比较标准说明。定义越具体，判定越一致。
save_dir（必填）保存中间产物与结果的目录（自动创建）。
modelgpt-5.4-mini使用的模型名；默认从环境变量 LEXIMETER_MODEL 读取。
n_rounds5对决轮数。每轮结束后用全部历史重新拟合一次，轮次越多排名越稳。
matches_per_round3每段文本每轮参与的对决场数。
learning_rate0.1拟合时的小平滑量（伪计数），防止出场次数少的文本得分过于极端。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
additional_instructionsNone追加给模型的任何额外指令（如补充比较标准）。
modality"text"文本类型提示："text"（段落）或 "entity"（短实体）。影响提示词措辞。
n_attributes_per_runNone（全部分批）每次对决请求最多包含几个属性。属性很多时模型可能顾此失彼，设小一点更稳。
circle_firstNone是否固定把某段文本放在提示词的 circle 位置。None = 每次随机，消除顺序偏差。
file_name"rankings"结果文件名前缀：最终汇总文件为 {前缀}_final.csv，每轮对决记录为 {前缀}_round{k}.csv。
reset_filesFalseTrue 时清空 save_dir 重新跑；False 时断点续跑（回放已完成轮次）。
client / embedding_client / search_toolNone底层客户端；默认自动从环境变量配置，一般不用改。
**engine_kwargs—透传给模型调用的额外参数（如 max_output_tokens、temperature、timeout、max_retries）。

完整参数与进阶选项见 ⚙️ 参数设置。
