过滤 filter

按一句自然语言条件筛选文本：只保留符合条件的行，其余筛掉。

文本整理类LLM 核心

这是什么

你的数据里往往混着大量与主题无关的文本。例如你要研究"科技新闻标题"，但抓回来的标题里有一半是天气、生活琐事。你想先筛掉无关的，再对剩下的做评分、编码。这类条件常常无法用关键词表达清楚：

  • "宣布产品或服务发布的新闻标题"——"Apple announces iPhone 17" 符合，"Weather forecast calls for rain" 不符合
  • "提及具体政策内容的段落"——需要理解句义而不是匹配词
  • "讨论工作压力的评论"——"Funding ran dry" 是，夸午餐的就不是

filter 让你把条件写成一句自然语言，模型逐条判断"是否符合"，符合的 keep 列为 True。相当于请一位认真的助理把表格过一遍，只留下符合你条件的行。

什么时候用 数据量大、想先砍掉无关文本再做深度分析时；或者你想得到"符合某条件的行子集"用于子样本比较。如果筛选之后还要给每行打分，可以用 评分 rate（评分不做丢弃，每行都保留分数）；要按标签分几类而不是二选一，用 分类 classify。

怎么用

给一个 DataFrame、列名和一句条件即可。返回原表 + 两个新列：keep（是否保留）和 score（符合程度，0–1）。

import leximeter
import pandas as pd

# 你的数据：一列"文本"
df = pd.DataFrame({"text": [
    "Apple announces iPhone 17 with foldable display.",
    "I made toast this morning and it was fine.",
    "Tesla begins deliveries of the Cybertruck in Europe.",
    "Weather forecast calls for rain on Tuesday.",
    "OpenAI ships GPT-6 API in public beta.",
    "My cat slept through the entire meeting.",
]})

# 条件写成一句自然语言
result = await leximeter.filter(
    df, "text",
    condition="The text announces a product launch or shipment.",
    save_dir="my_study/filter",
    model="deepseek-v4-flash",       # 或任何已配置的模型
)

回到数据里

用 result[result["keep"]].to_csv("kept.csv") 把筛出的行另存，或直接 result["keep"] 作为筛选标记参与后续分析。模型的原始回答在 save_dir/filter_responses_raw_responses.csv。

实现原理（简版）

关键挑战是"漏判"：模型面对一大串条目时，埋在中段的条目容易被看漏。做法：

  1. 分批：把所有唯一文本随机打乱（固定种子 random_seed，每次运行结果可复现），切成每批 entities_per_call 条（默认 150）的小清单。打乱是为了避免"同一来源的文本挤在同一批"造成的批次效应。
  2. 多次复测：每批独立问模型 n_runs 遍——"逐条评估是否满足条件，只输出满足的条目，一个都不能漏"。模型被要求检查清单中每条，包括埋在中段的。
  3. 计票与判定：每个文本被点名几次 ÷ 总遍数 = score（0–1）；score ≥ threshold（默认 0.5）则 keep = True。多次判断降低了模型偶尔看漏或误报的影响——只被点到一半遍数的文本会被滤掉，只有稳定命中的才保留。

给模型的提示词（概括）

Filter 提示词结构（简化为要点） 判定条件："…你的条件…"。
逐条评估下面清单中的每个实体是否满足条件，每一条都要看，不许跳过。
只输出满足条件的实体，漏掉任何一条都不行，也不许混入不满足的。
输出 JSON：{"entities meeting condition": ["…", …]}，实体名必须逐字照抄。

如果配置了 System One 协议的 Decision Provider 或传入 decision_client 与 decision_model，filter 会改走反向扇出路径：将筛选条件 condition 作为共享上下文状态，把去重后的候选条目批量提交为并行 noul 问题，单轮即可直接获得每条文本的校准概率 score 与 keep 判定，不消耗输出 token。

参数设置

参数默认值说明
condition必填筛选条件，写成一句自然语言，例如 "The text announces a product launch or shipment."。
save_dir必填保存中间产物与结果的目录，不存在时自动创建。
modelgpt-5.4-nanoLLM 路径使用的模型名，默认从环境变量 LEXIMETER_MODEL 读取。
decision_modelNoneDecision Provider 使用的模型名。使用 SystemOneClient 时必须显式传入或配置 LEXIMETER_DECISION_MODEL。
n_runs1LLM 路径每批评估几遍。大于 1 时 score 为命中遍数除以总遍数。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
entities_per_call150每批最多放多少条文本。批次越大越省调用，但 LLM 路径也越容易漏看。
shuffleTrue是否先打乱顺序再分批，以避免批次效应。
random_seed42打乱顺序的随机种子，固定后每次运行的分批方式一致。
threshold0.5保留判定线，score 达到该值时 keep = True。想更保守地过滤可调高，例如 0.8。
additional_instructionsNone追加给模型的额外指令，例如对条件的补充澄清。
file_namefilter_responses.csv结果文件名前缀，原始响应存为 filter_responses_raw_responses.csv，清洗结果存为 filter_responses_cleaned.csv。
reset_filesFalseTrue 时清空当前任务检查点重新运行；False 时断点续跑。更换模型、切换 Provider 或修改筛选条件时，过期检查点会自动失效重算。
client / decision_client / embedding_client / search_toolNone按次注入自定义 Provider 实例，默认自动从环境变量配置。显式传入 client= 时，环境变量中的 Decision Provider 不会自动接管。
