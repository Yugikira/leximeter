改写 paraphrase

让大语言模型按你写好的指令改写每一段文本——把口语换成正式书面语、压缩长度、统一术语表述——并自动校验改写是否真的做到了指令要求。

文本整理类LLM 核心

这是什么

你有一段段文本，想按统一规则把它们"整理"成另一种表述。例如：

  • 把网络俚语改写为正式书面语，再进入后续分析或发表
  • 把每个回答压缩到 50 字以内，便于做摘要对比
  • 把不同受访者对同一事物的称呼统一成一致术语（短实体模式）

输出有两列：改写结果（默认 text_revised，即"原列名 _revised"）和校验标记（text_revised_approved）。开启多轮校验后（n_rounds > 1），模型还会自己当"质检员"：没达到指令要求的改写会自动重写一轮，直到通过或轮数用尽。

什么时候用 当你的研究需要"语体统一、可公开、可比对"的文本时——比如把口语化访谈转成书面语供人工核对，或把产品描述统一风格后做比较研究。注意：如果目标只是删掉敏感信息而基本保留原话，请用 脱敏；只需给整段文本贴"是/否"标签用 分类；要在原文中按类别逐字标片段用 编码。

怎么用

三步：准备数据 → 写清改写指令 → 调用。指令（instructions）越具体，改写越稳定。

import leximeter
import pandas as pd

# 1. 你的数据：一列"文本"
df = pd.DataFrame({"text": [
    "u up? we should totally hit that new spot tmrw",
    "the boss is a total tool, no cap",
    "idk why they kept the old server up tbh",
    "lowkey hyped for the on-device models tho",
]})

# 2. 改写指令（告诉模型怎么改）
instructions = "Rewrite in a formal register, no slang."

# 3. 调用
result = await leximeter.paraphrase(
    df, "text",
    instructions=instructions,
    save_dir="my_study/paraphrased",
    model="deepseek-v4-flash",   # 或任何已配置的模型
)

回到数据里

返回的表格就是在原表上追加了改写列与校验列。设 n_runs=2 会生成 text_revised_1、text_revised_2 等多份改写。保存后建议重点抽查 approved=False 的行（多轮模式下才会出现），人工修正即可。

实现原理（简版）

整个过程不需要你理解细节，但知道原理有助于判断结果质量：

  1. 生成：对每段文本、每次改写，拼出一段标准指令（见下），并发发送给模型（默认 50 路并行，失败自动重试）。单轮模式（n_rounds=1）到此为止，所有改写直接标记"通过"。
  2. 校验（仅 n_rounds>1）：每轮为"尚未通过"的条目多生成几个候选改写（第一轮 n_runs 个，之后 n_runs × later_round_run_multiplier 个），然后用分类器逐条判定："改文是否忠实应用了指令、对原文做了符合要求的转换"。"通过"和"不确定"都算过，只有明确"未遵循"才算失败。
  3. 递归循环：失败的条目进入下一轮，从原文重新生成（若 use_modified_source=True，则从上一版改文继续，做增量改进）；直到全部通过或轮数上限用尽。
  4. 兜底：轮数用尽仍未通过时，从最后一轮候选中随机保留一个，approved 标为 False，提醒你人工处理。

给模型的提示词（概括）

Paraphrase 提示词结构（简化为要点） 以下是需要改写的内容："…原文…"。
任务：按下列指令改写，务必勤勉、彻底、忠实于指令。
BEGIN INSTRUCTIONS
…你的指令…
END INSTRUCTIONS
只输出改写后的文本，不要任何前言或解释。

多轮模式下还隐藏一道"校验提示词"：把「指令 + 原文 + 改文」一起发给分类器，问"改文是否忠实运用了指令对原文进行转换"，返回 True/False。这就是改写的质量闸门。

参数设置

参数默认值说明
instructions（必填）改写指令：告诉模型怎么改（语体、长度、角度……）。越具体越稳定。
column_name（必填）数据中文本所在列的列名。
save_dir（必填）保存中间产物与结果的目录（自动创建）。
modelgpt-5.4-mini使用的模型名；默认从环境变量 LEXIMETER_MODEL 读取。改写与校验共用同一个模型。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
modality"text"输入类型："text"（段落）、"entity"（短实体，如产品名）等，影响提示词措辞。
json_modeFalseTrue 时要求模型只输出 JSON（适合程序化解析）。
revised_column_nameNone自定义改写结果列名；默认 {"{column_name}_revised"}。
file_nameparaphrase_responses.csv原始改写响应的保存文件名；清洗后的结果存同名 _cleaned.csv。
n_rounds1校验轮数上限。1 = 单轮改写、不校验；大于 1 时启用"生成 → 校验 → 重写"循环。
n_runs1每段文本生成几份改写。大于 1 时输出列带 _1.._n 后缀；也是第一轮的候选数量。
later_round_run_multiplier5第二轮起每个条目生成的候选数 = n_runs × 该倍数（倍数不逐轮累乘）。
use_modified_sourceFalseTrue 时后续轮从上一版改文继续改写（增量改进），False 则始终回到原文。
validation_attributeNone自定义校验标签定义（默认为"是否遵循指令"）；多条目时取第一个。
reset_filesFalseTrue 时清空 save_dir 重新跑；False 时断点续跑（跳过已完成条目）。

完整参数与进阶选项见 ⚙️ 参数设置。
