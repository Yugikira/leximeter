分类 classify

让大语言模型对每段文本逐一判断"哪些标签适用"，得到一列列布尔（是/否）标记，直接把定性文本变成可以做统计的二值变量。

测量类LLM 核心

这是什么

你有一段段文本，你想给每段文本贴上"标签"——每段文本可以同时命中零个、一个或多个标签。例如：

  • 每条推文是否讨论政治、是否采用第一人称
  • 每段新闻是否属于新闻标题语体、是否涉及动物
  • 每段访谈回答是否提到了工作压力、是否提到了家庭支持

classify 对每段文本、每个标签给出一个 true/false 判定，并额外附一列 predicted_classes 汇总该文本命中的所有标签。相当于请一位认真负责的助理，按你写好的标签定义逐条勾选"适用/不适用"。

什么时候用 当你的研究需要把文本变成"是/否"标记时——回归里的哑变量（dummy）、分组比较的依据、筛出符合某条件（如含论点、提到某话题）的样本。如果你需要的是"强弱程度"的连续分数，用 评分；需要从文本里抽出具体事实（年份、价格）用 抽取；需要相对排序用 排序。

怎么用

三步：准备数据 → 定义标签 → 调用。数据是一个表格（pandas DataFrame 或 CSV），其中一列是你的文本。

import leximeter
import pandas as pd

# 1. 你的数据：一列"文本"
df = pd.DataFrame({"text": [
    "I heard that the new president instituted a law on gun control.",
    "My dog decided to eat food at 3am.",
    "Congress passes amended budget for 2026",
]})

# 2. 定义标签（键 = 标签名，值 = 给模型的判定标准说明）
labels = {
    "discusses politics":        "The text discusses politics.",
    "news headline":             "The text reads like a news headline.",
    "discusses animals":         "The text discusses animals.",
    "first person perspective":  "The text is written in the first person.",
}

# 3. 调用（save_dir 会存下所有中间文件，方便检查与续跑）
result = await leximeter.classify(
    df, "text",
    labels=labels,
    save_dir="my_study/labels",
    model="deepseek-v4-flash",   # 或任何已配置的模型
)

回到数据里

返回的表格就是在你原来的表格上追加了每个标签一列（true/false）。可以直接 result.to_csv("labels.csv") 保存，再导入 Stata / R 做交叉表或回归。

使用 Decision Provider（v0.2.0）

如果配置了 System One 协议的 Decision Provider，或显式传入 decision_client 与 decision_model，classify 会在单次前向传播中并行评估全部标签，直接返回校准概率且不产生输出 token 费用。传入 include_probabilities=True 时，输出表会额外包含每个标签的 {label}_prob 列；成对比较模式 differentiate=True 则使用三选一 choice 问题，将正反命题直接绑定到随机顺序的选项中，从结构上保证互斥。

import os
from leximeter.client import SystemOneClient

decision_client = SystemOneClient(
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)
result = await leximeter.classify(
    df, "text",
    labels=labels,
    save_dir="my_study/labels_decision",
    decision_client=decision_client,
    decision_model="cloudflare/clef-flash",
    include_probabilities=True,
)

实现原理（简版）

整个过程不需要你理解细节，但知道原理有助于判断结果质量：

  1. 生成提示词：将静态指令、标签定义与输出格式放在前缀，待测文本放在末尾，以最大化服务端前缀缓存命中率。相同文本只评估一次，结果复用。
  2. 并行执行：全部任务并发发送给模型（默认 50 路并行），失败自动重试，完成一批存一批。使用 Decision Provider 时，每条文本的多个标签在同一批 noul 或 choice 问题中并行完成。
  3. 解析：LLM 路径要求模型输出 JSON（{"标签名": true/false}）并解析为布尔值；Decision Provider 路径直接读取校准概率并与 min_frequency 比较，同时将原始概率写入检查点。
  4. 聚合（多次复测取多数决）：如果设置了 n_runs > 1，同一文本会被独立测量多次。判定为"是"的次数占比达到 min_frequency（默认 0.6，约等于 5 次里至少 3 次）才最终记为 True，降低单次抽样的随机波动。某标签所有测量都缺失时记为空值。

给模型的提示词（概括）

Classify 提示词结构（前缀固定，简化为要点） 请逐一判断下方标签是否适用，输出 JSON：{"标签名": true 或 false}。
规则：可多选，命中的标签都标 true；每个标签独立判断，不要互相推断；只依据文本内容判断。
标签定义清单（静态前缀，固定在顶部以复用 KV 缓存）。
待判断文本："…文本…"（动态内容放在末尾）。

标签定义写得越具体（例如"新闻标题"指什么、边界在哪里），不同文本之间的判定就越一致，这和问卷里把题目措辞写清楚是同一个道理。

参数设置

参数默认值说明
df必填你的数据表格（pandas DataFrame），须包含文本列。
column_nameNone单列模式下的文本列名；成对模式 differentiate=True 时改传 circle_column_name 与 square_column_name。
labels必填字典，键为标签名，值为判定标准说明。定义越具体，判定越一致。
save_dir必填保存中间产物与结果的目录，不存在时自动创建。
modelgpt-5.4-miniLLM 路径使用的模型名，默认从环境变量 LEXIMETER_MODEL 读取。
decision_modelNoneDecision Provider 使用的模型名。使用 SystemOneClient 时必须显式传入或配置 LEXIMETER_DECISION_MODEL。
n_runs1每段文本判定几次。大于 1 时按多数决聚合，并额外保存逐次明细供信度分析使用。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
min_frequency0.6判定门槛。LLM 路径为多次运行中判"是"的比例，Decision Provider 路径为校准概率阈值。
n_attributes_per_runNone每次请求最多包含几个标签。标签较多时设小一点更稳定。
differentiateFalse是否开启成对对比分类模式，需配合 circle_column_name 与 square_column_name 使用。
circle_firstNone成对模式下是否固定将 circle 放在前面。默认 None，每条随机以消除位置偏差。
include_probabilitiesFalse使用 Decision Provider 时是否在输出表中追加 {label}_prob 校准概率列。
order_strategy"per_run"标签键序策略："per_run"（同 run 固定以命中前缀缓存，跨 run 互异置换）、"fixed"（跨 run 固定）或 "per_item"（逐条随机打乱）。
additional_instructionsNone追加给模型的额外指令，例如带标注示例以校准判定。
modality"text"文本类型提示，可选 "text"（段落）或 "entity"（短实体）。
file_name"classify_responses.csv"中间结果文件名，最终汇总文件为同名 *_cleaned.csv。
reset_filesFalseTrue 时清空当前任务检查点重新运行；False 时自动断点续跑。更换模型、切换 Provider 或修改标签配置时，过期检查点会自动失效重算。
client / decision_client / embedding_client / search_toolNone按次注入自定义 Provider 实例，默认自动从环境变量解析。显式传入 client= 时，环境变量中的 Decision Provider 不会自动接管。
**engine_kwargs无透传给底层批处理引擎或模型调用的额外参数，例如 max_output_tokens、temperature、timeout 与 warmup_first。

完整参数与进阶选项见 ⚙️ 参数设置。
