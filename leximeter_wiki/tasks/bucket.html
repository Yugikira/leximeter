归桶 bucket

把你的大量原始条目（术语、观点、主题词）自动归纳成一组互斥的"桶"（大类），每个桶附一句带代表条目的定义——开放式编码里的"类别提炼"。

质性分析类LLM 核心

这是什么

你的数据里可能有成百上千个条目——词频表里的术语、对比任务产出的差异词、访谈中反复出现的主题词。你想把它们归并成 bucket_count 个互斥、具体的大类。例如把

  • smartphone、laptop、tablet、desktop computer、e-reader → 个人计算设备
  • wireless earbuds、over-ear headphones、bluetooth speaker → 无线音频设备
  • smartwatch、fitness tracker → 可穿戴健康追踪设备

每个桶都带一句定义（说明"落入该桶意味着什么"，并列出代表条目）。归桶过程不是一次提问，而是三阶段投票：先生成大量候选桶，再让模型反复投票归约，最后逐轮锁定最优桶——比单次提问稳定得多，也避免了"其他/杂项"式空桶。

什么时候用 当你条目太多、手工归类不现实时：词频表先归大类再做描述统计；把 compare 输出的差异词归纳成稳定的差异模式（记得 differentiate=True，桶名会保留"哪边更多"的方向）；或给 编码 的动态模式结果做二次归并。逐条目打"是/否"标签用 分类。

怎么用

三步：准备条目 → 指定桶数 → 调用。结果写入 bucket_definitions.csv。

import leximeter
import pandas as pd

# 1. 你的数据：一列"条目"（术语、观点、主题词……）
terms = pd.DataFrame({"term": [
    "smartphone", "laptop", "tablet", "smartwatch", "desktop computer",
    "wireless earbuds", "over-ear headphones", "bluetooth speaker",
    "fitness tracker", "e-reader",
]})

# 2. 调用（要求归成 3 个互斥大类）
result = await leximeter.bucket(
    terms, "term",
    bucket_count=3,
    save_dir="my_study/buckets",
    model="deepseek-v4-flash",   # 或任何已配置的模型
)

条目也可以带定义（每格是 {"条目": "定义"}），归桶时定义会一并参与，结果更准。

回到数据里

返回 bucket + definition 两列。之后可以把每个原始条目映射到最匹配的桶（例如用一个分类任务），得到"条目 → 大类"的归并表，再做计数与交叉分析。

实现原理（简版）

  1. 生成候选：把条目随机打乱、重复 repeat_bucketing 次、分批（每批 n_terms_per_prompt 条），让模型各自提出一组候选桶（带定义）；所有候选去重合并，存 bucket_generation.csv。
  2. 投票归约：多轮"多数投票"——每轮把当前候选分批、抽样条目，让模型从中投票选出最好的桶（每轮重复 repeat_voting 次），按得票排序后只保留 max(bucket_count, 现有数 × next_round_frac) 个，循环归约到 3 × bucket_count 以内。
  3. 终选补足：继续投票，每轮锁定 top_k_per_round 个得票最高的桶（已锁定的不再参与投票），直到凑齐 bucket_count 个。
  4. 断点续跑：每一步进度都写进 bucket_state.json（候选、票数、已锁定桶），中断后重跑会自动接着做；最终文件 bucket_definitions.csv 已存在时直接返回。条目的内容签名（terms_signature，条目带定义时按 "条目::定义" 计算）一旦变化，旧状态自动作废重跑。
  5. 方向性：differentiate=True 时条目是"两两对比的差异词"，桶名必须明确方向（如 "square entries 比 circle entries 更多地提到 X"），同一属性的两个方向会被当作不同桶。

给模型的提示词（概括）

Bucket 提示词结构（简化为要点） 以下是原始条目："…条目列表…"。
提出恰好 N 个更宽泛的"桶"概念：互斥、具体、有实质内容，
共同覆盖尽量多的条目；不要 "其他/杂项/单一" 式空桶；
宁可过具体，不要过模糊。输出 JSON：
{"桶名": "定义（1–3 句，含代表条目）"}
（投票轮改为：只能从候选桶中选择，已锁定的桶不得再选。）

"生成 — 投票 — 锁定"的三阶段设计，让每个候选桶都要过多数票检验，结果比单次提问更稳健、可重复。

参数设置

参数默认值说明
column_name（必填）数据中条目所在列的列名。单元格可以是字符串，也可以是 {条目: 定义} 字典或条目列表。
save_dir（必填）保存中间产物（各轮投票、状态文件）与结果的目录（自动创建）。
bucket_count10最终归成几个互斥大类。
modelgpt-5.4-mini使用的模型名；默认从环境变量 LEXIMETER_MODEL 读取。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
additional_instructionsNone追加给模型的任何额外指令（如限定归并角度、提供示例校准）。
differentiateFalseTrue 时条目被当作"两类内容之间的差异词"，桶名必须保留方向（square/circle 哪边更多），两个方向视为不同桶。
n_terms_per_prompt250每次请求最多包含多少个条目（或候选桶）。条目很多会自动分批。
repeat_bucketing5生成阶段：打乱条目、重复提议候选桶的次数。越大候选池越丰富。
repeat_voting25每轮投票重复的次数。越大票数越稳。
next_round_frac0.25归约轮每轮保留的候选比例（下限为 bucket_count）。
top_k_per_round1终选阶段每轮锁定的最高票桶数。大于 1 可加快凑齐桶数。
raw_term_definitionsTrue条目是否携带定义参与归桶（影响 terms_signature 的签名内容）。
file_namebucket_definitions.csv最终结果文件名；已存在时直接返回（断点续跑）。
reset_filesFalseTrue 时删除 bucket_state.json 重新跑；False 时从断点继续。

完整参数与进阶选项见 ⚙️ 参数设置。
