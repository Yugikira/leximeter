合并 merge

把两张表格按"意思相同但写法不同"的键连接起来——左表叫 "Apple Inc."，右表叫 "Apple, Inc."，merge 会认出它们是一回事。

文本整理类LLM 核心

这是什么

你经常需要把两个数据源按某个"键"合并：访谈数据里受访者提到的公司名，对接工商名录里的正式名称；问卷调查里的城市名，对接人口普查代码。问题是两边写法往往不一致：

  • 标点格式不同："Apple Inc." 与 "Apple, Inc."、"Google Incorporated"
  • 缩写与别名："JFK" 与 "John Kennedy"
  • 面子上不同、意思却相同："minneapolis" 与 "Hennepin County"、"heart rhythm doctor" 与 "927 - Cardiac Electrophysiology"

merge 逐行检查左表的键，在右表里寻找含义最接近的键并配对。匹配上的行会把右表其余列一并接进来；找不到匹配的行保持空缺。相当于请一位很谨慎的助理做"模糊匹配"——宁可不配，绝不乱配。

什么时候用 两个数据源说的是同一批实体（公司、城市、机构、人名……）但命名体系不同，需要合并成一张表做分析。如果两边键完全一致（连大小写、标点都一样），用 pandas 自带的 pd.merge 即可，不必动用模型。需要把一列里的重复概念归一化而不是跨表连接，用 去重 deduplicate。

怎么用

准备左表、右表，各指定一个"键列"，调用即可。数据是 pandas DataFrame 或 CSV。

import leximeter
import pandas as pd

# 左表：你的研究数据（比如访谈中提到的公司）
df_left = pd.DataFrame({
    "company_id":   [1, 2, 3],
    "company_name": ["Apple Inc.", "Google Inc.", "Tesla Inc."],
})

# 右表：另一个来源的名录（拼写五花八门）
df_right = pd.DataFrame({
    "record_id": [101, 102, 103, 104],
    "name":      ["Apple, Inc.", "Google Incorporated",
                  "Tesla, Inc.", "Distractor Company 1"],
})

# 调用：左表键列 = company_name，右表键列 = name
result = await leximeter.merge(
    df_left, df_right,
    left_on="company_name", right_on="name",
    how="left",                      # 保留左表全部行
    save_dir="my_study/merge",
    model="deepseek-v4-flash",       # 或任何已配置的模型
)

8 个左表键全部在第一次尝试内匹配（进度文件显示 attempt 0：匹配 8，剩余 0），这批耗时约 10 秒。"Inc." 与 "Inc," 仅差一个逗号，模型全部正确配对，16 个干扰项无一误配。

回到数据里

返回的表格 = 左表全部行 + 右表匹配到的列（未匹配的行这些列为空）。可以直接 result.to_csv("merged.csv") 保存。原始的模型回答保存在 save_dir/merge_responses.csv，每轮进度在 merge_progress.csv，方便检查匹配质量。

实现原理（简版）

知道原理有助于判断结果质量。整个过程分四步：

  1. 自动匹配（先捡走最稳的）：把两边的键都换算成"向量"——可以想象成地图上的一个点，意思越近的点靠得越近。若左表某键与右表某键的相似度 ≥ 0.75（auto_match_threshold）且候选唯一，就直接判定匹配，不再麻烦模型。
  2. 聚类 + 候选窗口（把意思相近的名字先在地图上聚成堆）：剩下的键用聚类算法（kmeans2）分成若干堆，每堆里的键意思相近，再按相似度为堆里每个键挑出最可能的右表候选。第一轮每堆最多 16 个左表键（short_list_len），候选上限 256 个；没匹配上的进入下一轮，窗口缩小为 8 → 4 → 2（每轮 × 0.5），同时扫描更多候选窗口（candidate_scan_chunks），给难配的键更多机会，直到轮数用尽（max_attempts）。
  3. 细问：每堆发一个提示词——"为每个短名单词，在长名单里找最接近的匹配；没有把握就写 no certain match"。模型返回 JSON 映射。
  4. 汇总与拼接：如果 n_runs > 1，同一问题问多遍、投票取多数，平票时用向量相似度裁决；答案为 "no certain match" 的放弃。最后把同键同写的各组展开回原表，完成拼接。

两个实用细节：合并前键会自动做"归一化"（小写、去重音、去标点）——所以 "Café" 和 "cafe" 天然视为同一写法；无 embedding 环境时自动退化为按字母序分堆的纯 LLM 路径。

给模型的提示词（概括）

Merge 提示词结构（简化为要点） 下面是短名单（待匹配）与长名单（候选）。
为每个短名单词在长名单中找唯一的最佳匹配，写法不同但意思相同也算（如 "Mary Monroe" ↔ "Marilyn Monroe"）。
找不到匹配就写 "no certain match"——宁可漏配，绝不乱配。
输出 JSON：{"短名单词": "长名单词或 no certain match"}，词必须逐字照抄，不得改动。

提示词刻意强调"宁缺毋滥"：错误的匹配比没有匹配更有害，所以模型默认非常保守。

参数设置

参数默认值说明
onNone两边键列同名时的简写；与 left_on / right_on 二选一。
left_on / right_onNone左表 / 右表中用于匹配的键列列名。
how"left""left" 保留左表全部行；"right" 保留右表全部行。
save_dir（必填）保存中间产物与结果的目录（自动创建）。
modelgpt-5.4-nano使用的模型名；默认从环境变量 LEXIMETER_MODEL 读取。
n_parallels50同时发送给模型的请求数。API 允许时越高越快。
n_runs1每个匹配问题问几遍；大于 1 时投票取多数，降低偶然错误。
additional_instructionsNone追加给模型的任何额外指令（例如你已知的同义对照表）。
short_list_len16每组最多放几个待匹配的左表键（第一轮）。
long_list_len256每个键最多纳入多少个右表候选。
use_embeddingsTrue是否用向量相似度预筛候选并做自动匹配；关闭时退化为按字母序分堆。
max_attempts4匹配轮数上限；每轮窗口收缩并换新候选。
short_list_multiplier0.5每轮窗口收缩倍率（16 → 8 → 4 → 2）。
auto_match_threshold0.75自动匹配的相似度阈值；达到且候选唯一时直接匹配，不再问模型。
use_best_auto_matchFalse多个候选同时超过阈值时，是否直接取相似度最高的（默认否——宁可交给模型细看）。
candidate_scan_chunks5第二轮起，每堆额外扫描几个候选窗口，给难配的键更多机会。
order_strategy"per_run"候选列表键序策略："per_run"（同 run 固定以命中前缀缓存，跨 run 互异置换）、"fixed"（跨 run 固定）或 "per_item"（逐条随机打乱）。
verboseTrue是否在运行中打印每轮的匹配进度。
file_namemerge_responses.csv原始模型响应保存的文件名。
reset_filesFalseTrue 时清空 save_dir 重新跑；False 时断点续跑（跳过已完成部分）。
