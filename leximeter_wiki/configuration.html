参数设置

Leximeter 的每个功能都有大量参数，但 90% 的情况下你只需要改三样东西：你的数据、你的衡量标准（attributes/labels/categories）、保存位置（save_dir）。本页是全部参数的速查字典。

一、全局配置（环境变量与 .env 文件）

在项目根目录的 .env 文件中配置一次，所有任务共用。系统环境变量的优先级高于 .env。

变量默认说明
LEXIMETER_PROTOCOLresponsesLLM 接口协议：responses（OpenAI Responses API）或 chat（Chat Completions，适用于 DeepSeek、MiniMax、Ollama、vLLM）。
LEXIMETER_BASE_URL未设置模型服务地址，例如 https://api.deepseek.com。
LEXIMETER_API_KEY未设置模型 API 密钥；未设置时回退到 OPENAI_API_KEY。
LEXIMETER_MODELgpt-5.4-mini默认生成模型名，代码里不指定 model= 时生效。
JSON_LLM_MODELgpt-5.4-minisafest_json 解析失败时的兜底修复模型。
LEXIMETER_EMBEDDING_PROVIDERlocal文本嵌入 Provider：local（本地 BGE 模型，需安装 [embeddings]）、openai（兼容 API）或 none（禁用，任务自动走纯 LLM 路径）。
LEXIMETER_EMBEDDING_MODELBAAI/bge-m3嵌入模型名，使用 openai 时例如 text-embedding-3-small。
LEXIMETER_EMBEDDING_BASE_URL同 LLM 地址嵌入服务的独立端点，仅 openai 模式使用。
LEXIMETER_EMBEDDING_API_KEY同 LLM 密钥嵌入服务的独立密钥，仅 openai 模式使用。
LEXIMETER_SEARCH_PROVIDERnone联网搜索 Provider：tavily 或 none。启用 tavily 时需要配置 TAVILY_API_KEY。
LEXIMETER_DECISION_PROTOCOLnoneDecision Provider 协议：systemone、dummy 或 none。未启用时所有任务自动回退到 LLMClient。
LEXIMETER_DECISION_BASE_URL未设置System One 服务根地址，例如 https://openrouter.ai/api 或 AMD Radeon Token Factory 端点。
LEXIMETER_DECISION_API_KEY未设置Decision Provider API 密钥。
LEXIMETER_DECISION_MODEL未设置默认决策模型名，例如 cloudflare/clef-flash 或 d3-flash。使用 SystemOneClient 时必须通过此变量或 decision_model= 显式指定，不会回退到生成模型。

二、所有任务共有的参数

参数默认说明
model环境变量或任务默认本次调用使用的生成模型名，可与全局配置不同以混用多模型。
save_dir任务默认目录检查点与结果文件的保存目录，不存在时自动创建。建议每个研究单独设一个目录。
n_parallels50并发请求数。服务端不限流时可适当调高。
reset_filesFalse设为 True 时清空当前任务的检查点与状态文件从头重跑。设为 False 时自动断点续跑，跳过已完成条目；复杂任务在输入不变时直接加载本地结果。如果模型、Provider 类型或提示词配置发生变化，子阶段过期检查点会自动失效并重新计算。
max_retries0仅 discover、debias、ideate、poll、seed 支持。整个任务抛出非参数类异常时，自动以 reset_files=False 从检查点重试的次数。单次请求重试由底层 SDK 负责，不叠加。
client / decision_client / embedding_client / search_toolNone按次注入自定义 Provider 实例，覆盖 .env 默认值。在单阶段任务中显式传入 client= 时，环境变量中的 LEXIMETER_DECISION_PROTOCOL 不会强行接管。

三、Decision Provider 与前缀缓存优化（v0.2.0）

v0.2.0 新增两项面向成本与质量的核心能力：

  • Decision Provider（decision_client 与 decision_model）。通过 SystemOneClient 对接 POST /v1/systemone 决策模型（支持 OpenRouter 44 款模型、TypeSafe Jev、AMD Radeon Token Factory、vLLM 与 SGLang），单次前向传播并行评估多个类型化问题，直接返回校准概率且无输出 token 计费。classify、rank、filter 支持纯 Decision 路径；discover、paraphrase、codify、debias 支持混合路径，即生成阶段走 LLMClient、内部判断子阶段走 DecisionClient。
  • 前缀固定提示词与 order_strategy。全部 14 份提示词模板已调整为静态说明与量表置顶、动态文本置底。rate、classify、extract、rank、codify、merge 均支持 order_strategy 参数：默认 "per_run" 在同一次 run 内固定键序以命中前缀缓存，并在多次 run 间使用互异确定性置换抵消顺序偏差；"fixed" 在跨 run 间始终复用原始键序以最大化热缓存；"per_item" 保留上游逐条随机打乱行为。
  • 自适应首条预热（warmup_first）。通过 **engine_kwargs 透传给 batch_execute，默认 None。当待处理请求数超过 max(8, n_parallels) 时，先顺序发送首条请求填充服务端前缀缓存，再并发放行其余请求，小批次无额外等待。

五、数据加载

函数参数
leximeter.load(folder_path)folder_path（必填，文本文件夹） · save_name（None） · modality（"text"，仅支持 text） · reset_files（False）。返回 path、name 与 text 三列。
参数调整的通用建议 先用几十条小样本验证输出质量，确认定义清晰后再跑全量。成本敏感时可以保持默认 order_strategy="per_run"（多次重复运行时也可改用 "fixed"），或在判断类任务中接入 Decision Provider。结果波动大时，提高 n_runs 并把属性定义写得更具体。
